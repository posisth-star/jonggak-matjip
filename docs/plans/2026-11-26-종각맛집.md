# 종각맛집 Implementation Plan (v2, 카카오)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 종각역 반경 1.6km 식당을 카카오 API에서 받아 음식 종류별로 보여주고, 식당마다 네이버·카카오 지도 링크를 다는 무료 정적 웹페이지.

**Architecture:** 서버 없는 정적 페이지. 브라우저가 카카오맵 JavaScript SDK `kakao.maps.services.Places#keywordSearch`를 직접 호출한다. 순수 로직(변환·필터·정렬·링크 생성)은 DOM·카카오와 분리된 ES 모듈로 두고 Node 내장 테스트로 검증한다. 종류 탭을 누를 때만 그 종류를 호출한다.

**Tech Stack:** HTML, 바닐라 JavaScript(ES modules), 카카오맵 JavaScript SDK(`libraries=services`), Node 26 `node --test`, GitHub Pages.

**Spec:** `종각맛집/docs/2026-11-26-종각맛집-design.md`

## Global Constraints

- 프로젝트 루트: `종각맛집/` (모든 경로는 이 기준). 이 폴더에서 `git init`.
- 중심점: 종각역 `{ lat: 37.5702, lng: 126.9831 }` (Task 1에서 카카오맵으로 재확인), 반경 `1600` m.
- 종류당 최대 45곳(15개 × 3페이지), 거리순(`SortBy.DISTANCE`)으로 받는다.
- 카카오 장소 정보는 **저장 금지**: localStorage/sessionStorage/파일 저장 없음. 페이지가 열려 있는 동안 메모리에만 둔다.
- 기본 정렬: 가까운 순. 대안: 이름순(`localeCompare('ko')`).
- 도보 시간: 카카오 `distance`(직선 m) × 1.3 ÷ 80 m/분, 반올림.
- 키: 카카오 JavaScript 키를 `config.js` 한 곳에만. 카카오 개발자 콘솔에서 JavaScript SDK 도메인에 배포 주소를 등록한 뒤에만 커밋한다. REST API 키는 쓰지 않는다.
- 화면 문구는 한국어. 파일은 UTF-8.

## Review Focus

1. 이름에 특수문자(`<`, `&`, 공백, `#`)가 있는 식당 → 화면은 이스케이프, 네이버 링크는 `encodeURIComponent`로 깨지지 않음 (Task 2 `naverSearchUrl encodes`, Task 3 `escapes name`).
2. 흔한 상호(예: "김밥천국")로 네이버 검색 시 다른 지점이 나옴 → 검색어에 "종각"을 붙임 (Task 2 `naverSearchUrl appends 종각`).
3. 결과가 0곳인 종류 → “이 종류는 주변에 등록된 식당이 없어요.” (Task 3 `renderList shows empty message`).
4. SDK 로드 실패·키 도메인 미등록·쿼터 초과 → “식당 정보를 불러오지 못했어요” (Task 3 `renderError`, Task 4 `fetcher rejects on ERROR status`).
5. 같은 탭을 여러 번 눌러 중복 호출 → 종류별 결과를 페이지 세션 동안 메모리에서 재사용, 실패 시엔 재시도 가능 (Task 4 `caches per key`, `retries after failure`).

### Task 2: 변환·정렬·링크 (순수 로직)

**Files:**
- Create: `src/places-logic.js`, `tests/places-logic.test.js`

**Interfaces:**
- Produces:
  - `Restaurant = { id, name, subCategory: string, distanceM: number, walkMin: number, phone: string, kakaoUrl, naverUrl }`
  - `toRestaurant(doc): Restaurant` — 카카오 결과 문서(`id, place_name, category_name, distance, phone, place_url`) 변환. `subCategory`는 `category_name`을 `' > '`로 나눈 마지막 조각(예: `"음식점 > 한식 > 국수"` → `"국수"`). `distance`는 문자열로 오므로 숫자로.
  - `walkMinutes(distanceM: number): number`
  - `matchesCategory(categoryName: string, category): boolean` — `category.match`가 `null`이면 true, 아니면 `categoryName.split(' > ')[1]`에 `match`가 포함될 때 true. 키워드 검색이 다른 종류 식당을 섞어 줄 때 걸러낸다.
  - `naverSearchUrl(name: string): string` → `'https://map.naver.com/p/search/' + encodeURIComponent(name + ' 종각')`. 구현 전에 이 형식이 브라우저에서 네이버 지도 검색 결과를 여는지 직접 한 번 확인하고, 다르면 실제 형식으로 바꾼다.
  - `sortRestaurants(list, sortBy: 'distance'|'name'): Restaurant[]` (원본 불변)
  - `dedupeById(list): Restaurant[]`

- [ ] **Step 1: 실패하는 테스트**

test('sort distance and name', () => { /* 3개로 거리순·이름순(가나다) 순서 단언 */ });
test('dedupeById keeps first', () => { /* 같은 id 2개 → 1개 */ });

### Task 4: 카카오 연동과 앱 연결

**Files:**
- Create: `src/kakao.js`, `src/app.js`, `config.example.js`, `tests/kakao.test.js`
- Modify: `index.html` (`src/app.js` 모듈 연결만. SDK `<script>` 태그는 넣지 않는다)

**Interfaces:**
- Consumes: `CATEGORIES`, `CENTER`, `RADIUS_M`, `toRestaurant`, `matchesCategory`, `dedupeById`, `sortRestaurants`, `render*`
- Produces:
  - `SdkAdapter = { location, sortDistance, Status: { OK, ZERO_RESULT, ERROR } }` — 테스트에선 가짜 값, 실제론 `new kakao.maps.LatLng(CENTER.lat, CENTER.lng)`, `kakao.maps.services.SortBy.DISTANCE`, `kakao.maps.services.Status`.
  - `searchAllPages(keywordSearch, category, sdk: SdkAdapter): Promise<doc[]>` — `keywordSearch(query, callback, options)`를 감싸 최대 3페이지를 모음. 옵션: `{ location: sdk.location, radius: RADIUS_M, category_group_code: category.groupCode, sort: sdk.sortDistance, size: 15, page }`. 콜백 status가 `sdk.Status.OK`면 누적, `ZERO_RESULT`면 지금까지 모은 것으로 종료, `ERROR`면 reject. `pagination.hasNextPage`가 false거나 3페이지면 종료.
  - `createFetcher(keywordSearch, sdk: SdkAdapter): (categoryKey) => Promise<Restaurant[]>` — `searchAllPages` → `matchesCategory(doc.category_name, category)`로 거름 → `toRestaurant` → `dedupeById`. 같은 key는 첫 Promise 재사용, 실패 시 캐시에서 제거.
  - `loadKakaoSdk(appKey: string): Promise<void>` (`src/app.js`) — `<script src="https://dapi.kakao.com/v2/maps/sdk.js?appkey=${appKey}&libraries=services&autoload=false">`를 동적으로 추가하고 `kakao.maps.load` 완료 시 resolve, 스크립트 `onerror` 시 reject. 키는 `config.js`의 `KAKAO_JS_KEY`에서만 읽는다.
- 구현자가 [카카오맵 Web API 문서](https://apis.map.kakao.com/web/documentation/)에서 `Places#keywordSearch` 옵션명(`page`, `size`, `sort`)과 페이지 이어 받기 방식(`page` 옵션 vs `pagination.nextPage()`)을 확인해 맞춘다.
